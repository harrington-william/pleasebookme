## 2. INTENT

Replace the reserved "Widgets" nav entry with a working page that lets a
workspace admin see, filter, create, edit and soft-delete the booking widgets
embedded on their websites — and make it feel like the rest of the dashboard:
quiet, precise, expensive, and unhurried.

Two screens:

1. **`/dashboard/widgets`** — title + description, two stat tiles ("Active
   Widgets", "Disabled"), a type/status filter bar, and a card grid where each
   card shows name, status, type, and registered origin, with **Quick Edit**
   and an inline-confirm **delete**.
2. **`/dashboard/widgets/new`** and **`/dashboard/widgets/[id]`** — one
   `WidgetEditor` in two modes, three steps: **Basics** (name, type — Inline
   only), **Security** (allowed origin, generate/rotate key pair), **Review**
   (everything, grouped Basics/Security, then Save → back to the list).

## 6. CONSTRAINTS

### Security is deferred by explicit decision

Same as TASK-0007 §6. The client performs no authorization. `organizationId`
is resolved server-side via `resolveCurrentPlatformUser` and sent as a query
parameter, exactly as the resources page does. Do not add client-side
ownership checks; do not hide UI based on roles.

The secret key is the exception to "nothing sensitive here":

- It exists in browser memory only inside the editor's form state, between
  "Generate key pair" and Save (or Cancel / navigation away). It is never
  written to `localStorage`, `sessionStorage`, a cookie, the URL, or a
  Server Component prop.
- The BFF `POST /api/widgets/credentials` passes it through once and must not
  log the response body. `POST /api/widgets` and `PUT /api/widgets/[id]`
  forward it inside the JSON body and must not log the request body.
- No response other than the credentials route ever contains it — the platform
  guarantees that; the client must not reconstruct it (e.g. by keeping the
  generated pair in a React context that outlives the editor).

### Client (from `client/AGENTS.md` — read it first)

- **This is not the Next.js in your training data.** Read
  `client/node_modules/next/dist/docs/01-app/` for route handlers, `params` /
  `searchParams` as Promises, `cookies()` async. `proxy.ts`, not middleware.
- zod is **v4**: `z.url()`, `z.enum([...])`, `{ error: "…" }`.
- Tailwind v4 tokens in `app/globals.css`; **no raw hex**. Dark only.
- `cn()` for every dynamic className; plain strings for static ones.
- shadcn `base-nova`: `Switch` needs `<Controller>` and `inputRef`.
- Never import `serverEnv()`, `lib/session.ts`, or any `*-gateway.ts` into a
  Client Component.
- Every Bearer call goes through `withAccessToken`; Server Components pass
  `{ allowSessionWrite: false }`.
- **Redirect-loop invariant**: a Server Component redirects to
  `SESSION_EXPIRED_REDIRECT`, never bare `/login`.
- `window.confirm` is banned. Inline confirm, as `DeleteServiceButton`.
- No `any`, no non-null `!` to silence the compiler.
- Copy shapes from `features/services` and `features/resources`; do **not**
  extract shared components from them in this task. If the third copy of
  `StatTile` / pagination bothers you, note it in the closing report as a
  follow-up. Scope discipline beats DRY here.

### Design (from `design/client/DESIGN.md` prose — the frontmatter is stale)

- Level 0 canvas `bg-background`, Level 1 panels `bg-surface` with
  `border-border`, hover brightens the border (`hover:border-surface-hover`),
  never lifts.
- Radius: `rounded-lg` (10px) for controls and cards, `rounded-xl` for section
  panels (matches `Section`), `rounded-[6px]` for nested buttons,
  `rounded-sm` for chips.
- Type: `text-headline-lg(-mobile)` page title, `text-headline-md` card /
  section titles, `text-body-md` everything else, `text-label-md` uppercase
  tracking-wider for property labels, `font-mono text-mono-label` for keys,
  origins, ids.
- Spacing on the 4px grid only: `gap-md` between related elements, `p-lg`
  inside panels, `py-xs` inside property rows.
- Status: 6px solid dot (`size-1.5 rounded-full`), chips at 10% tint. No
  pulsing. Desaturated semantic colors via `text-success` / `text-warning` /
  `text-destructive` tokens.
- Motion: `transition-colors` only. No scale, no slide, no fade-in on mount.

## 7. DEPENDENCIES

### TASK-0007 — the wire contract (must be COMPLETED first)

```text
POST   /api/v1/widgets/credentials              200  { publicKey, secretKey }
POST   /api/v1/widgets                          201  Widget
GET    /api/v1/widgets?organizationId=&type=&status=&page=&size=&sort=
                                                200  { content: Widget[], page, size, totalElements, totalPages }
GET    /api/v1/widgets/stats?organizationId=    200  { total, active, disabled, revoked }
GET    /api/v1/widgets/{widgetId}               200  Widget          (404 WidgetNotFound)
PUT    /api/v1/widgets/{widgetId}               200  Widget          (409 WidgetRevoked)
DELETE /api/v1/widgets/{widgetId}               204                  (soft delete → REVOKED)

Widget = { widgetId:number, widgetUid:string, tenantId:number, name:string,
           status:"REGISTERING"|"ACTIVE"|"DISABLED"|"REVOKED",
           type:"INLINE"|"POPUP"|"FULL_PAGE"|"EMBEDDED",
           originValidation:boolean, publicKey:string, origin:string|null,
           issuedAt:string, expiresAt:string|null, lastUsedAt:string|null,
           createdAt:string, updatedAt:string }

WidgetCreateRequest = { name, type?, origin?:string|null,
                        credentials:{ publicKey, secretKey } }
WidgetUpdateRequest = { name, type?, status?:"ACTIVE"|"DISABLED", origin?:string|null,
                        credentials?:{ publicKey, secretKey }|null }

publicKey  ~ ^pbm_pk_[A-Za-z0-9_-]{22}$
secretKey  ~ ^pbm_sk_[A-Za-z0-9_-]{43}$
```

Facts that shape the UI:

- The list **never** contains `REVOKED` widgets; `total` excludes them;
  `revoked` is reported separately.
- `origin` in responses is **normalized** (`scheme://host[:port]`). The platform
  rejects an unparseable origin with **400** and a platform-shaped message —
  show it verbatim.
- `409` on `POST /widgets` means the public key already exists (regenerate);
  `409` on `PUT` means the widget is revoked.
- `404 TenantNotFoundException` on any widget call means the signed-in
  workspace predates tenant provisioning — a dev-data condition, not a UI bug.
  Surface it as the load error text, do not special-case it.
- `expiresAt` is always `null` from this flow. Do not render it.

## 9. FUNCTIONAL REQUIREMENTS

### 9.1 The design language, stated once

Calm infrastructure. The page should read as a control surface for something
that is already running, not a marketing card deck. Concretely:

- **Hierarchy through weight and tone, not size.** One `headline-lg` on the
  page; `headline-md` on cards; everything else `body-md` / `label-md`.
  Secondary metadata is `text-muted-foreground`; primary text is
  `text-foreground`; pure white never appears.
- **Borders separate, color does not.** Panels are `bg-surface` outlined with
  `border-border`. Inset areas inside a panel (key display, toggle rows,
  type cards) drop to `bg-background`. The only saturated color on the list
  page is the primary CTA and the success/warning dots.
- **Monospace signals machine-facing values.** Public keys, origins, and the
  `01 / 02 / 03` step numerals are `font-mono text-mono-label`. Nothing else
  is.
- **Quiet motion.** `transition-colors` on hover/focus. No entrance
  animations, no skeleton shimmer (the pages are Server Components; data is
  there on first paint).
- **Whitespace is the luxury.** `gap-lg` between page sections, `p-lg` inside
  panels, `p-2xl` page padding on `md+`. Cards are not crowded: two property
  rows, an action footer, and air.

### 9.3 The editor — shell and stepper

`WidgetEditor` (`"use client"`) owns one `useForm<WidgetFormValues>` with
`zodResolver`, `mode: "onBlur"`. All three step panels stay mounted; the
active one is displayed (`TabPanel` from the services editor, copied). The
step lives in **`?step=basics|security|review`**, default `basics`, unknown →
`basics`. `WIDGET_STEP_QUERY_KEY = "step"`. Server pages never read
`searchParams` *(comment — same reason as the services editor)*.

`WidgetEditorShell` — **not** the services left rail. A wizard reads
top-to-bottom:

```text
← Back to widgets                                   text-body-md muted, ArrowLeft

Create Widget                                       headline-lg
Set up an embeddable booking widget in three steps. body-md muted

┌─────────────────────────────────────────────────────────────────────────┐
│ [01] Basics          │ [02] Security          │ [03] Review              │
│      Name and type   │      Origin and keys   │      Confirm and save    │
└─────────────────────────────────────────────────────────────────────────┘
   rounded-xl border-border bg-surface p-xs · three equal Link cells, gap-xs
   cell: rounded-lg px-md py-sm flex items-center gap-sm  (stack under md)
   numeral box: size-6 rounded-[6px] font-mono text-mono-label
     active   → bg-primary/10 text-primary border border-primary/30 ; cell bg-surface-hover
     complete → bg-success/10 text-success  (Check icon replaces numeral)
     upcoming → border border-border text-muted-foreground
   label body-md ; sub-label label-md muted ; aria-current="step" on active
   every cell is a Link with scroll={false} → `${pathname}?step=…`

<form max-w-3xl>
  [ AuthFormAlert when submitError ]
  [ active step panel ]
  footer: flex items-center justify-between gap-sm
     left : ghost "Back" (hidden on basics)
     right: step 1–2 → primary "Continue" ; step 3 → primary "Save Widget" / "Save Changes"
            + "Cancel" link (text-destructive, → /dashboard/widgets)
</form>
```

- "complete" is computed, not stored: a step is complete when
  `trigger(fieldsForStep)` would pass on current values — evaluate with
  `getFieldState`/`formState.errors` and the step's `fields` list, the same
  list `onInvalid` uses. Keep it cheap: derive from `watch()` of the step's
  fields, no effect.
- **Continue** calls `await trigger(STEP_FIELDS[active])`; on success
  `router.replace(`${pathname}?step=${next}`, { scroll: false })`. On failure
  the field errors are already rendered; focus the first invalid control.
- Steps are freely navigable via the stepper. Gating lives in **Continue** and
  in **Save** (§9.5), not in the links — a user going back to fix something
  must not be trapped *(comment)*.
- Step panels use `Section` from `service-form-primitives.tsx` with an eyebrow
  above the `h2`: `p.font-mono.text-mono-label.text-muted-foreground`
  "STEP 01 · BASICS".

Edit mode differences: title "Edit Widget", description "Update this widget's
details, origin and keys."; stepper identical; Save label "Save Changes".

```ts
export const PUBLIC_KEY_PATTERN = /^pbm_pk_[A-Za-z0-9_-]{22}$/;
export const SECRET_KEY_PATTERN = /^pbm_sk_[A-Za-z0-9_-]{43}$/;
// UX guardrail only. The platform normalises and is the authority (TASK-0007 §9.4).
export const ORIGIN_PATTERN = /^(https?:\/\/)?[a-z0-9-]+(\.[a-z0-9-]+)*(:\d{1,5})?(\/.*)?$/i;

const credentialsSchema = z.object({
  publicKey: z.string().regex(PUBLIC_KEY_PATTERN),
  secretKey: z.string().regex(SECRET_KEY_PATTERN),
});

export const widgetFormSchema = z.object({
  name: z.string().trim().min(1, { error: "Name is required" }).max(255, { error: "Keep the name under 255 characters" }),
  type: z.enum(WIDGET_TYPES),
  enabled: z.boolean(),
  origin: z.string().trim().max(255).refine(v => v === "" || ORIGIN_PATTERN.test(v), { error: "Enter a website like https://barbershop.com" }),
  credentials: credentialsSchema.nullable(),
});
export type WidgetFormValues = z.infer<typeof widgetFormSchema>;

// Create needs a pair; edit does not. Same object, one extra rule.
export const createWidgetFormSchema = widgetFormSchema.refine(
  v => v.credentials !== null, { error: "Generate a key pair first", path: ["credentials"] }
);

export const DEFAULT_WIDGET_FORM_VALUES: WidgetFormValues =
  { name: "", type: "INLINE", enabled: true, origin: "", credentials: null };

export function toEditWidgetFormValues(widget: Widget): WidgetFormValues
  // name, type, enabled: widget.status === "ACTIVE", origin: widget.origin ?? "", credentials: null

// Wire payloads — what the BFF re-validates and forwards.
export const widgetCreatePayloadSchema = z.object({ name, type, origin: z.string().nullable(), credentials: credentialsSchema });
export const widgetUpdatePayloadSchema = z.object({ name, type, status: z.enum(["ACTIVE","DISABLED"]), origin: z.string().nullable(), credentials: credentialsSchema.nullable() });
export function toWidgetCreatePayload(v): WidgetCreatePayload   // origin: v.origin === "" ? null : v.origin
export function toWidgetUpdatePayload(v): WidgetUpdatePayload   // status: v.enabled ? "ACTIVE" : "DISABLED"
```

### 9.6 API interaction — who calls what

```text

  query = parseWidgetQuery(await searchParams)
  withAccessToken(token => listMyWidgetsOnPlatform(token, actor.subject, query), { allowSessionWrite: false })

  getSessionActor() ──none──▶ 401
```

   `WidgetStepSection` (same classes + the `STEP 01 · BASICS` eyebrow + an

   (the already-normalised body short-circuits first), so `createWidget`
   rewrites its 409 message after normalising. Documented in `AGENTS.md`.

   submitting — a small UX addition; the implicit-submission rule would have
   done nothing anyway because no submit button is mounted on those steps.
5. `toWidgetCreatePayload` takes `WidgetFormValues & { credentials:
   WidgetCredentials }` so the create path narrows once in `onSubmit` instead
   of carrying an unreachable empty-string fallback.

One thing worth knowing that the contract did not anticipate: a stepper click
