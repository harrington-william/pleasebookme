```
GET /api/v1/booking-resources?organizationId={id}-> every link in the org (batch)
```

### 10.3 Paginated, org-scoped bookings list

Replace the unscoped `getBookings()`.

```
GET /api/v1/bookings

    &tab=              (optional, BookingTab — defaults to UPCOMING)
    &serviceId=        (optional)
    &resourceId=       (optional)
```


- `BookingRepository` additionally extends `JpaSpecificationExecutor<BookingEntity>`.
- `hasOrganization` traverses `root.get("service").get("organization").get("organizationId")`.
- `hasResource` requires a subquery or join into `core.booking_resources`; if
  that proves awkward inside a `Specification`, **drop the `resourceId` filter

#### Sort and page size

- Default sort **`startTime` DESC**. Whitelist: `startTime`, `endTime`, `title`,
  `status`, `createdAt`, `updatedAt`. `MAX_PAGE_SIZE` 100, default page size 20.

> **Flagged, not changed:** `startTime` DESC on the default `UPCOMING` tab puts
> the *furthest-future* booking first, so the next thing happening is at the
> bottom of the page. ASC reads more naturally there. The task author specified
> DESC; implement DESC. Raise it in the closing report, do not switch it.

#### Tabs — `BookingTab`

The mock has no tab bar; it has a **Status column** showing Confirmed / Pending /
Cancelled. The tab set below is derived from that plus the five `BookingStatus`
constants, and is the authoritative specification for this task.

`BookingTab` is a **query concept, not a database enum.** It lives in
`core/booking/specification/`, is a plain Java enum, and gets **no Postgres type
and no migration**. Adding one is Escalation #1.

| Tab | Predicate | Meaning |
|---|---|---|
| `UPCOMING` | `endTime >= now` AND `status IN (PENDING, ACCEPTED, AWAITING_HOST)` | **Default.** Live work still ahead. |
| `PENDING` | `status IN (PENDING, AWAITING_HOST)` | Needs a decision from the host. No time constraint — an overdue request still needs answering. |
| `PAST` | `endTime < now` AND `status IN (PENDING, ACCEPTED, AWAITING_HOST)` | Elapsed and not cancelled. |
| `CANCELLED` | `status IN (CANCELLED, REJECTED)` | Both terminal negatives, one tab. |
| `ALL` | unrestricted | Escape hatch. |

Three consequences that are easy to get wrong:

1. **There is no `COMPLETED` status.** `BookingStatus` has no terminal success
   state, so `PAST` is a **time** predicate over `endTime`, never a status
   predicate. Do not add a status constant to make this tidier — that is a
   schema change (Escalation #1).
2. **`PENDING` deliberately overlaps `UPCOMING` and `PAST`.** The tabs are
   views, not a partition. A pending booking next Tuesday appears in both
   `UPCOMING` and `PENDING`, by design.
3. **`now` is captured once, in the service method, and passed into the
   specification.** Do not call `Instant.now()` inside the spec lambda:
   `findAll(spec, pageable)` issues a count query and a content query, the lambda
   is evaluated for both, and a booking ending in the microseconds between them
   can be counted but not returned — a page whose `totalElements` disagrees with
   its own `content`. Rare, real, and miserable to debug.

`matchesTab(BookingTab tab, Instant now)` returns
`Specification.unrestricted()` for `ALL`. A null or unparseable `tab` resolves
to `UPCOMING` **in the controller**, so the service always receives a concrete
value.

The tab replaces the standalone `status` query parameter — the two would be a
redundant axis that can contradict each other. There is no `?status=`.

**No tab counts in this phase.** Badging each tab with a count means five extra
count queries per page load. Render the bar without counts; note it as a
deliberate omission.

### 10.4 Cancel

```
GET /api/v1/bookings/{bookingId}/cancel  -> 200 BookingResponse
```

Sets `status = CANCELLED` and returns the updated booking.

- **Idempotent.** Cancelling an already-`CANCELLED` booking returns 200 with the
  unchanged row. Not a 409.
- Does **not** set `cancelledBy` — that needs the calling principal, and §6 puts
  principal resolution out of scope. Leave the column null. Note this in the
  closing report.
- Does not set `cancellationReason`. No request body.
- Unknown id → `BookingNotFoundException` → 404 via the existing handler.

> **Flagged, and deliberately specified this way by the task author:** `GET`
> mutates state here, which browser prefetch, link crawlers and caching proxies
> can trigger without a user acting. `POST` would be the conventional verb.
> **Implement it as `GET` as specified — do not silently change it.** The
> concern is recorded here so the decision is visible, not so it gets reversed
> mid-task.

### 10.6 The list page

`/dashboard/bookings`, Server Component, mirroring
`app/dashboard/resources/page.tsx` exactly: session check → `parseBookingQuery`

**Three columns, in this order:**

| Column | Source |
|---|---|
| Customer | the booking's attendee `name` + `email`, with derived initials. Multiple attendees → show the first (lowest `attendeeId`) and a `+N` affordance. No attendees → `—`. |
| Service | `service.title`, resolved from the org's service list. |

**The tab bar** sits above the table: Upcoming · Pending · Past · Cancelled ·


`resourceLookup` is §10.9's endpoint, **not** the paginated resource list —
using the latter caps the Staff column at one page of resources.

then builds `Map`s and joins in memory. One request per row is a task failure,

### 10.7 The detail panel

Hidden until a row is clicked, then slides in on the right — the Notion page
behaviour.

- **State lives in the URL**: `?booking={bookingId}`, preserved alongside the
  existing filter/page params. A table row is a `<Link>`, so the panel is
  linkable, back-button-able, and survives refresh. Do not hold it in React
  state.
- Close (`×`) navigates back to the same URL minus `booking`.
- An unknown or non-matching `?booking=` renders no panel and no error — the

Contents, top to bottom:

1. `BK-XXXXXXXX` (§5) + status badge.
2. Booking `title`.
3. **Edit** (disabled, reserved) and **Cancel** (functional, inline confirm).
4. BOOKING DETAILS — Date, Time, Staff, Location.
   - Date/Time render from `startTime`/`endTime` (`Instant`, UTC on the wire).
     Format in the **organization's** timezone, labelled with the zone. Do not
     silently render browser-local time in a Server Component — that is a

   - Staff is the primary resource's name, `—` when none.
   - Location is `bookings.location` verbatim, `—` when null.
5. ATTENDEE — name, email, phone, timezone, and a no-show indicator when

### 10.8 Cancel, end to end

`app/api/bookings/[bookingId]/cancel/route.ts` → `withAccessToken` → the
platform's `GET .../cancel` → returns the updated booking. On success the client
calls `router.refresh()`. Errors normalize through `lib/api-error.ts`.

Note the BFF route's own verb is a `POST` even though the platform call it makes
is a `GET` — a browser-initiated state change should not be a `GET` on our own
origin. This asymmetry is intentional; keep it.

### 10.9 Resource lookup

```
GET /api/v1/resources/lookup?organizationId={id} -> List<ResourceLookupResponse>
```

`ResourceLookupResponse(BigInteger resourceId, String name)` — nothing else.

**Why this endpoint exists.** The Staff column resolves
`booking_resources.resourceId` to a resource *name*, so the gateway needs a
name-by-id map for the whole organization. The existing
`GET /api/v1/resources?organizationId=` is **paginated** (default 20, max 100),
so reusing it would return the first page only and every booking whose resource
falls outside it would render `—` — wrong, and silently so. Requesting
`size=100` moves the ceiling without removing it.

Unpaginated is consistent with existing practice here: the resource-type list is
already unpaginated "for form selection" for the same reason.

- Add `ResourceLookupResponse` to `resource/resources/dto/`, a
  `getResourceLookupByOrganizationId` service method, and the controller
  mapping. Reuse the existing `ResourceRepository`; add a derived finder only if
  one is genuinely missing.
- Map `/lookup` **before** any `/{resourceId}` mapping in the controller so the
  literal segment is not swallowed by the path variable.
- Do not touch `ResourceResponse`, `ResourceEntity`, or the existing list
  endpoint.
